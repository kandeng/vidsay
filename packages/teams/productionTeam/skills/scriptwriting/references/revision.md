# 修订轮方法

round > 1 时执行修订，原则是**最小必要改动**：

1. 先读 reviews 里最新一份反馈，把意见逐条分类：结构性（场景增删、顺序）、内容性（人物、对白、基调）、表述性（措辞、格式）。
2. 从上一版 vN-1 出发修改，不推倒重写；未被批评的场景与对白保持原文，让用户能确认"改了哪里"。
3. 意见之间冲突或与大方向冲突时，不擅自仲裁：选择一种处理写进剧本，同时在 notes.md 和报告 openQuestions 里说明冲突与备选方案。
4. 反馈含糊（如"感觉不够好"）时，找出最可能对应的具体维度做一处克制改进，并在 openQuestions 里请用户确认方向。
5. 报告的 changes 只列**本轮相对上一版**的改动（不是相对草稿），before 写上一版的处理，方便用户对照。
6. 新版本号 = round；vN.md 与 vN.json 同时更新，旧版本文件不动。
